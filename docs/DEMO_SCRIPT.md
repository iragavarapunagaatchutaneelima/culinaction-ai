# Demo Script (2–3 minutes)

**Setup before the demo:** run `npm run build` and `npm start`, then open http://localhost:8787 (or use `npm run dev`). Create the owner account. Use a phone-width browser window or Chrome device mode to show the mobile layout.

> Say this up front: "This demo uses the **illustrative workspace**. It is synthetic sample data that CulinAction generates and labels on every screen. It is not a real Hyderabad restaurant, and none of these numbers are real-world results."

| Time | Do                                                                                                        | Say                                                                                                                                                                                                                                                               |
| ---- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00 | Outlets screen → **Create illustrative workspace**                                                        | "Real outlets start empty. You enter your own stock, recipes and sales. For the demo I'm using clearly labelled sample data." Point at the striped banner.                                                                                                        |
| 0:15 | **Today**                                                                                                 | "Today shows what needs attention: food-safety checks, tasks, approvals, the last service, and missing information."                                                                                                                                              |
| 0:30 | **Inventory → Milk**                                                                                      | "Stock is held in batches with the date printed on the pack. One milk batch is past its use-by date, so it is excluded from usable stock automatically. Cashew nuts are past best-before and need a quality check before they count."                             |
| 0:45 | **Menu → Medu Vada / Ven Pongal**                                                                         | "Vada has no recipe and Pongal's recipe is not verified, so neither is used in calculations. We never invent recipes."                                                                                                                                            |
| 0:55 | **Recommendations → Run decision engine**                                                                 | "The engine uses fixed, documented rules on these records. It is not a chatbot. Results are grouped: food safety first, then service risks, cost and data quality."                                                                                               |
| 1:10 | Open **"Prepare fewer Upma"** (also try the Idli batter expiry risk or the Potato stockout)               | Walk through **Problem → Compare options A/B/C → calculation → supporting batches, recipe quantities and sales → missing information → safety checks**. "Every number traces back to a record. Forecasts are simple same-weekday averages, and the page says so." |
| 1:35 | Point at the **AI-written** panel                                                                         | "AI is optional and only rewrites this in plain words. No key is configured here, so it says _not configured_. It never invents an explanation."                                                                                                                  |
| 1:45 | Choose an option → **Create draft plan** → edit the quantity → **Submit** → **Approve**                   | "Nothing happens until an owner or manager approves. The original and edited quantities and the approval history are kept."                                                                                                                                       |
| 2:05 | **Prep & tasks → Mark done** (enter the actual quantity) → **Record outcome now** → sold/discarded → Save | "After service, staff record what actually happened. That deducts ingredients and adds sales."                                                                                                                                                                    |
| 2:25 | **Analytics**                                                                                             | "Measured values are labelled _Actual_, calculated ones _Estimate_. This prep task can't be judged yet: we need at least three earlier outcomes, so the app shows that instead of claiming a saving."                                                             |
| 2:40 | Close                                                                                                     | "Recommendation → approved action → verified outcome. What's proven: the workflow and calculations, with 88 automated tests. What isn't: real-world savings. That needs a real outlet recording data for a few weeks."                                            |

## Optional extras if time allows

- **Sales → Import CSV:** upload a file with an unknown dish and a bad quantity to show the row-by-row review.
- **Phone width:** the bottom navigation and the "More" sheet.
- **Settings:** roles, data export (CSV with formula-injection protection), audit log.
